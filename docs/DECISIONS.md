# Decisions

Decisions taken after the phase 0 report (`docs/inventory/REPORT.md`, section 13) and during phase 1. Each entry says what was decided and where it is implemented.

| # | Topic | Decision | Implemented in |
|---|---|---|---|
| D0 | No silent stubs (spec principle 4) | Refined: a no-op is allowed only when doing nothing cannot change any result. Every such case is listed with a justification in `manifests/noop-allowlist.txt`. Everything else either works or fails with an error and a stderr message. | `manifests/noop-allowlist.txt` |
| D1 | Phase 1 scope | The layer declares everything `libmri` needs. Functions that are not implemented yet fail with `errno = ENOSYS` and print a message once. They are listed in `manifests/enosys.txt`, which must shrink. Real implementations first for what runs in `3dinfo`/`3dcalc`/`3dTstat`. | `compat/`, `manifests/enosys.txt` |
| D2 | `fork`+`exec` | Every `fork` call site gets a patch. The layer provides `posix_spawn[p]`/`waitpid` via `CreateProcess`. | `patches/0002`, `compat/src/process.c` |
| D3 | `fork` without callers | Patched out. `fork` is not declared by the layer, so a new upstream use fails to compile. | `patches/0003`, `patches/0004` |
| D4 | Build description | Upstream CMake + `cmake/toolchain-mingw.cmake` + minimal build-file patches. NIfTI from the in-tree copy via `FETCHCONTENT_SOURCE_DIR_NIFTI_CLIB`. | `patches/0001`, `tools/build.py` |
| D4a | GIFTI (**deviation from D4**) | The in-tree `src/gifti/CMakeLists.txt` cannot be used through `FETCHCONTENT_SOURCE_DIR_GIFTI_CLIB` (it downloads nifti_clib master again and redefines the NIfTI targets). `FETCHCONTENT_SOURCE_DIR_GIFTI_CLIB` points to `cmake/gifti/`, which builds the in-tree `src/gifti/gifti_io.c` and `gifti_xml.c` as `GIFTI::giftiio`. No upstream code is copied. **Drift risk:** this is our own build description of an upstream library; if upstream adds sources, definitions or dependencies to gifti, `cmake/gifti/` will not follow automatically. The build fails loudly only if the two source files disappear. | `cmake/gifti/CMakeLists.txt` |
| D5 | `libmri` | Shared library (DLL), as upstream builds it by default. | upstream default `BUILD_SHARED_LIBS=ON` |
| D5a | Compat library | `afni_compat.dll` (not a static library as the spec originally said). A static layer linked into both `libmri.dll` and each program would have two copies of its state (`rand48` seed, child process table, …). | `compat/CMakeLists.txt` |
| D6 | `alarm` watchdog in `3dQwarp` | Patched out under `_WIN32`. `alarm` is not declared. The toolchain links with `-Wl,--wrap=alarm`, and `compat/CMakeLists.txt` fails the configure step if `alarm` still links, so MinGW's silent stub can never be used. | `patches/0006`, `cmake/toolchain-mingw.cmake`, `compat/CMakeLists.txt` |
| D7 | Signals | Installing a handler for `SIGPIPE`/`SIGBUS` is an allowed no-op; `mallopt` would return 0 without a message (allowlist). Other signals that Windows does not have: `SIG_ERR` + `ENOSYS` + message. | `compat/src/signal.c` |
| D8 | `popen`/`system` | Run through `sh` from busybox-w32, which ships with the release. No own POSIX shell parser. Checked before implementation (phase 1 report, section 4). | phase 2 |
| D9 | SysV shm | Built with `DONT_USE_SHM`. The layer only provides `key_t`. `mmap` (including `MAP_ANON|MAP_SHARED`) stays in the layer. | `compat/include/afni_compat.h` |
| D10 | Program lists | Section 10 lists accepted, plus `3dAttribute 3dSynthesize 3dNotes 3dnewid` in required. | `manifests/programs-*.txt` |
| D11 | 64-bit offsets | `fseek`→`_fseeki64`, `ftell`→`_ftelli64` in the forced include; `_FILE_OFFSET_BITS=64`. | `compat/include/afni_compat.h` |
| D12 | Binary mode | MinGW-w64's `binmode.o` is empty in the UCRT CRT 13 used for the build, so the layer provides the `_fmode = _O_BINARY` definition itself (`afni_compat_binmode`, linked into every consumer) and switches stdin/stdout/stderr to binary in the DLL constructor. | `compat/src/binmode.c`, `compat/src/init.c` |
| D13 | Standard streams | stdin, stdout and stderr are in binary mode (no LF↔CRLF translation), as on Linux. Confirmed after phase 1. | `compat/src/init.c` |
| D14 | `PATH`-like lists, absolute paths | Directory lists are split at `THD_PATH_LIST_SEP` (`;` under `_WIN32`, `:` otherwise) and absolute names are recognised by `THD_IS_ABSPATH()` (also `X:/` and `X:\` under `_WIN32`); both macros are defined in `mrilib.h`. No `/c/...` paths through the layer. The audit found no name mistaken for a prefix because of a drive letter, 9 list-splitting sites and 10 absolute-path tests (8 from the audit, 2 working-directory checks in `SUMA_ParseFname` added after review); all of them use the macros. | audit: `docs/reports/colon-audit.md`; `patches/0007` |
| D15 | qhull | Taken from MSYS2 (`mingw-w64-ucrt-x86_64-qhull`), not built from upstream `src/qhulldir` (broken on Win64). All runtime files are listed in `manifests/runtime-deps.txt` with versions and licences. | `manifests/runtime-deps.txt` |
| D16 | `whereami`, atlases | `whereami` is optional. `AFNI_atlas_spaces.niml` ships with the release; atlas datasets do not, until their licences are checked. | `manifests/programs-optional.txt`, `manifests/runtime-deps.txt` |
| D17 | Real Windows check | A minimal CI workflow from phase 4 is brought forward: MSYS2 UCRT64 on `windows-latest`, build of `AFNI_26.2.09` with `tools.build`, `3dinfo`/`3dcalc`/`3dTstat` on the same data, comparison with a Linux build, bit-for-bit; differences are reported with their magnitude, the tolerance is not adjusted. Results obtained under wine are preliminary until this CI passes. | `.github/workflows/build-windows.yml`, `tests/regression/` |
| D18 | Line endings | Patches are always checked out with LF (`.gitattributes`: `*.patch text eol=lf`), because `actions/checkout` on Windows uses Git for Windows with `core.autocrlf=true` and CRLF patches do not apply to the LF upstream tree. Upstream is cloned with `core.autocrlf=false`, so the tree is byte-identical to the tag whatever git performs the build. | `.gitattributes`, `tools/build.py` |
| D19 | `make` in the Windows build | Upstream `assemble_target_list` (`src/CMakeLists.txt`) always runs `bash -c "make -sf Makefile.INCLUDE list_<component>"` at the end of the configure step; `REMOVE_BUILD_PARITY_CHECKS` does not skip it. MSYS2 `make` is installed in the build environment instead of patching the parity check out. | `.github/workflows/build-windows.yml` |
| D20 | Backslashes in paths | `\` is not treated as a directory separator. Paths given to AFNI programs on Windows must use `/` (`C:/data/anat+orig`), which Windows accepts everywhere. No `argv` rewriting in the layer and no patch of the places that split names at `/`. | `docs/reports/colon-audit.md`, section 7 |
| D21 | `HOME`, `TMPDIR` | Set by the layer when the DLL loads, only if unset: `HOME` from `USERPROFILE`, `TMPDIR` from `GetTempPath`, both with forward slashes. Upstream already prefers these variables over `/tmp` and `getpwuid`. Hard-coded `/tmp/` remains in the help search (`phelp_cmd`, `program_supports` in `thd_getpathprogs.c`) and is not mapped. | `compat/src/env.c` |
| D22 | Shell for `popen`/`system` | `busybox.exe` next to `afni_compat.dll` runs `sh -c`; `AFNI_COMPAT_SHELL` may name another POSIX `sh`. No shell found: `ENOENT` and one stderr message. Only the three standard handles are inherited (`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`), so pipes of other `popen` calls never leak into a child. The release also ships `gzip.exe` and `bzip2.exe` (copies of busybox; busybox-w32 picks the applet from the file name), because upstream checks for these programs on `PATH` before compressing (patch 0008). | `compat/src/shell.c`, `patches/0008` |
| D23 | Sockets | A Winsock socket is wrapped in a CRT descriptor (`_open_osfhandle`), so descriptor numbers never collide with files and `read`/`write` work. `close` is redirected to `afni_compat_close` in C code (closes the socket, then frees the descriptor). `select` and `fcntl` work on sockets only; other descriptors fail with `ENOSYS` (upstream uses them only on sockets). `fcntl(F_SETOWN)` is an allowed no-op. Winsock is loaded with `GetProcAddress` so that its import thunks do not clash with the layer's functions of the same names. | `compat/src/net.c`, `compat/src/winsock_bridge.c` |
| D24 | `dl*` | **Revised:** implemented (`LoadLibraryEx`/`GetProcAddress`/`FreeLibrary`), and `afni_compat.h` defines `DYNAMIC_LOADING_VIA_DL` and `DYNAMIC_suffix ".dll"`, so the NLfit model loader is compiled. Needed by the optional `3dTSgen` and `get_afni_model_PRF*`; the model libraries are built from `manifests/models-optional.txt`. `dlopen` flags are an allowed no-op. No required program and nothing in `libmri` depends on `ALLOW_PLUGINS`. | `compat/src/dl.c`, `compat/include/dlfcn.h` |
| D25 | `SIGQUIT` | Installing a handler is an allowed no-op (`3dQwarp`); `SIGKILL`/`SIGHUP` handlers are only in code compiled out by `DONT_USE_FORK`. | `compat/src/signal.c`, `manifests/noop-allowlist.txt` |
| D26 | `3dDeconvolve` without X11 (P7) | Patch 0009 builds an X-free `coxplot` (`COXPLOT_WITHOUT_X11` hides the declarations that need X11 types) and `3dDeconvolve` with `mri_coxplot.c` when `COMP_GUI` is off. `-xjpeg` needs `cjpeg` on `PATH`, as on Linux. `3dDeconvolve_f` is not defined (optional). | `patches/0009` |
| D27 | `3dttest++ -Clustsim` (P4) | Patch 0010 replaces `fork()` + `system()` in `start_job` with `afni_compat_spawn_shell()` (asynchronous `sh -c`, child registered for `wait()`). The layer implements `kill(SIGTERM/SIGKILL/0)` with `TerminateProcess` and `waitpid(-1)` for any number of children. The jobs run `3dttest++` and `3dClustSim` through `PATH`, so the AFNI directory must be on `PATH` (also true on Linux). | `patches/0010`, `compat/src/process.c`, `compat/src/shell.c` |
| D28 | Linux reference build | Official upstream CMake configuration (`.docker/cmake_build.dockerfile`: `COMP_GUI=ON`), with `COMP_SUMA`, `COMP_PYTHON`, `COMP_TCSH` off (out of scope), same in-tree NIfTI/GIFTI sources as on Windows. All 53 required programs, including `3dDeconvolve`, build there without afni-win patches. | `.github/workflows/build-windows.yml` |
| D29 | Regression tolerance (phase 5) | Supersedes the bit-for-bit rule of D17 for the full scenario. Classes fixed by mechanism in `tests/regression/tolerance.json`: direct arithmetic `rtol 1e-5` + `1e-6`·max\|ref\|; least-squares fits with transcendental regressors `1e-4`/`1e-5`; iterative optimisation `1e-2`/`1e-2`; printed numbers use the same absolute part (`atol_scale` times the largest number of the file) and also pass within one unit of the last printed digit. Outputs that are not reproducible upstream (verified by two Linux runs) are reported only. Exit codes must be 0 on both platforms; stderr is reported only. Random seeds fixed with `AFNI_RANDOM_SEEDVAL`, `OMP_NUM_THREADS=1` where OpenMP could change summation order. | `tests/regression/` |
| D30 | Release and failed tags (phase 4) | `watch-upstream-tags.yml` (daily) starts `build-windows.yml` with `publish=true` for at most 3 newest upstream tags not older than `manifests/upstream-baseline.txt` that have no `<tag>-win` release, no `Build failed: <tag>` issue (open or closed) and no running build. A failed publishing run opens that issue; the tag is then only rebuilt by a manual run, which closes the issue on success. An existing release is never overwritten. | `.github/workflows/` |
| D31 | Package contents | Programs that built (required + optional), all build DLLs and model DLLs, MSYS2 runtime DLLs found recursively from the import tables, busybox (+ `gzip.exe`, `bzip2.exe`), `qhull.exe`, `cjpeg.exe`/`djpeg.exe` (libjpeg-turbo, for `-xjpeg`), `AFNI_atlas_spaces.niml`, licences and a README with tag, commit and patches. The CI scenario runs from the package with `PATH` limited to it and the Windows system directories. | `tools/package.py` |
| D32 | Windows installer (requested separately, outside spec phases 0-5) | Inno Setup 6 wizard built in CI next to the zip and attached to the release as the recommended download. Per-user installation without administrator rights by default, all-users installation offered by the wizard; optional "Add AFNI to PATH" (on by default, removed again on uninstall); Start-menu shortcuts "AFNI Command Prompt" (cmd with AFNI on PATH and short instructions), "Getting started", documentation and uninstall. The wizard uses the Windows language through Inno's built-in translations; afni-win's own texts are English (repository rule). Not code-signed: SmartScreen shows a warning. CI installs silently, runs `3dcalc`/`3dinfo` with PATH taken from the registry and uninstalls. | `installer/`, `.github/workflows/build-windows.yml` |
| D33 | Scripting layer research (S0, outside spec phases 0-5) | Findings and the recommended strategy (A: MSYS2 `tcsh` and POSIX tools for scripts, native AFNI programs, native Python with a shell shim) in `docs/inventory/scripts-REPORT.md`; **the strategy is not chosen yet** (waits for confirmation, as are the QC report and paths with spaces). Two build options added for the prototype, both off by default so release builds do not change: `AFNI_WIN_EXTRA_PROGRAMS` (single-file programs that only `src/Makefile.INCLUDE` builds, e.g. `count_afni`) and `AFNI_WIN_PTAYLOR` (`src/ptaylor` without SUMA); `tools.build` passes them with `--extra-program` and `--cmake-define`. The prototype workflows (`scripts-prototype.yml`, `scripts-recompare.yml`, removed after S0) and `tests/scripts/` were research only. | `cmake/afni-extra-programs.cmake`, `tools/build.py`, `tests/scripts/`, `.github/workflows/scripts-*.yml` |
| D34 | Scripting layer: decisions after S0 | **Strategy A** (D33, `docs/inventory/scripts-REPORT.md`): MSYS2 `tcsh` and POSIX tools for the scripts, native AFNI programs, native Python whose shell commands go to the MSYS2 `sh`. **QC report**: not in the first phases (`-html_review_style none`); building the `afni` GUI under Cygwin/X is a later, separate research phase. **R** (`3dMVM`, `3dLMEr`, ...): in scope, together with the pipeline work. **Paths**: non-ASCII (Cyrillic) supported through `AFNI_ALLOW_ARBITRARY_FILENAMES=YES` set by the AFNI environment; paths with spaces are not supported, as upstream (fails in `afnipy` and the generated tcsh on Linux too), and the AFNI environment reports them with a clear error instead of failing in the middle of a pipeline. **Reference data** for CI: OpenNeuro `ds000102` `sub-08` (PDDL). | `docs/inventory/scripts-REPORT.md` section 10 |
| D35 | X-linked console programs without X11 (S1) | `3dSkullStrip` (SUMA) and `1dplot` use no display in batch use, but upstream links them with X11/Motif/OpenGL (libSUMA mixes computation and display code: 37 of its 43 objects are pulled into `3dSkullStrip`). `cmake/afni-nox.cmake` (`AFNI_WIN_NOX`, with `AFNI_WIN_PTAYLOR`) compiles `src/SUMA`, `src/avovk` and `1dplot` against X11/Motif/OpenGL headers only (`tools/x_headers.py`: Ubuntu 24.04 header packages pinned by sha512 in `manifests/x-headers.txt`, build time only) and links them with `afni_x_absent.dll` in place of the X libraries and of AFNI's `mrix`: upstream `suma_help.c`, `coxplot/plot_ts.c`, `mri_coxplot.c` (in-memory drawing) plus the 344 X entry points of `manifests/x-absent.txt`, generated as functions that print their name and exit with status 1 (no silent stubs). Checked on Linux by linking the same objects against the same generated library: `3dSkullStrip` (also `-orig_vol`) and `1dplot -jpg/-ps` give bit-identical output and never reach those functions; the Windows `3dSkullStrip` (wine) and `1dplot -ps` are bit-identical to Linux. `WIN32` is undefined for these targets and `cmake/x-headers-shim/GL/*.h` hide `_WIN32` from the GL headers, which otherwise include `windows.h`. Compat additions: `index`, `caddr_t`, `<sys/errno.h>`. PNG output needs `pnmtopng` (netpbm), which MSYS2 does not have; JPEG works (`cjpeg`). | `cmake/afni-nox.cmake`, `manifests/x-absent.txt`, `tools/x_headers.py` |
| D36 | `afni` program | The X11 GUI is not built. `programs/afni_console.c` is installed as `afni`: `-ver`/`-version`, `-vnum` and `-package` print exactly what upstream `afni` prints (same macros as `show_AFNI_version()` etc., compiled with `SHOWOFF` as upstream compiles `afni.c`), because every `afni_proc.py` proc script starts with `afni -ver`; any other use prints that the GUI is not part of the Windows build and exits with status 1. | `programs/afni_console.c` |
| D37 | Code page and long paths | Every executable linked with the compat layer carries a manifest with `activeCodePage` UTF-8 (so `argv`, `fopen` and the other narrow APIs use UTF-8 and Cyrillic file names work) and `longPathAware`. GCC links `default-manifest.o` from its startfile directories into every executable; `-B` points to the layer's own `default-manifest.o`, which therefore replaces MinGW's (a second manifest resource would collide). Needs Windows 10 1903 or later. | `compat/src/afni.manifest`, `compat/CMakeLists.txt` |
| D38 | Scripting runtime in the package (S2) | Strategy A (D34) shipped with every release. Layout of the package: programs in the root; `scripts/` with the upstream scripts of `src/scripts_install`, `src/python_scripts/scripts`, `src/scripts_for_r` and `src/R_scripts`, unchanged; `msys/` with the MSYS2 packages of `manifests/scripting-runtime.txt` and their dependencies (`pactree`), without documentation, headers and static libraries, and an `etc/fstab` that maps `/tmp` to the user's temporary directory; `python/` with UCRT64 Python, numpy and matplotlib, `afnipy` and the shell shim `afni_win_posix_shell` (loaded by a `.pth` file: `subprocess` with `shell=True` and `os.system` run `sh -c` from `msys/`, so `afnipy` sees a POSIX shell as on Linux); `R/` (D39). `afni-env.cmd` sets the environment (`AFNI_ROOT`, PATH = root, `scripts`, `msys/usr/bin`, `python/bin`, `R/bin`; `HOME` from `USERPROFILE` if unset; `AFNI_ALLOW_ARBITRARY_FILENAMES=YES`; `LANG=C.UTF-8`; `MPLBACKEND=Agg`; `PYTHONUTF8=1`, so the bundled Python writes UTF-8 to files and pipes as on Linux instead of the ANSI code page, which cannot encode e.g. a Cyrillic path that `afni_proc.py` prints) and refuses an AFNI directory or a current directory with a space (D34). `afni-tcsh.cmd` is the AFNI shell (Start menu "AFNI Shell"), `tcsh.cmd` runs tcsh with the environment, and each script has a `<script>.cmd` launcher that runs it with its interpreter, so scripts also start from `cmd.exe` and PowerShell. The installer proposes `C:\AFNI` and refuses a directory with a space. `SOURCES.txt` lists every bundled MSYS2 package version and where MSYS2 publishes its source; licence texts come with the packages. | `tools/scripting.py`, `manifests/scripting-runtime.txt`, `runtime/python/`, `installer/` |
| D39 | R for the AFNI R programs (S3) | **Deviation from the S3 plan** (MSYS2 `mingw-w64-r`): CRAN R for Windows, version and installer sha256 pinned in `manifests/r-runtime.txt`, with the CRAN packages that the R programs load installed as Windows binaries from a dated Posit Package Manager snapshot, so every build gets the same versions without compiling (MSYS2 has no binary packages for most of them). `tools/r_runtime.py` installs it silently in CI; the package carries it as `R/`. `R_io.so` (loaded by `AFNIio.R`) is built from upstream `src/R_io.c` against that R by `cmake/afni-rio.cmake` (a Windows DLL keeping the name `AFNIio.R` looks for); the Linux reference builds it with the same file against `libR.so`. Patch 0011: the R scripts split `PATH` at `:`, which breaks on drive letters; they use `.Platform$path.sep`. `runtime/r/Rprofile.site` (appended to `R/etc/Rprofile.site`) attaches a `system()` that runs commands with the bundled `sh -c`, because the R programs pass POSIX command lines to `system()`, which R on Windows runs without a shell. Not shipped: `brms` (Bayesian `RBA`/`MBA`, needs Stan and a compiler). | `manifests/r-runtime.txt`, `tools/r_runtime.py`, `cmake/afni-rio.cmake`, `patches/0011`, `runtime/r/` |
| D40 | Acceptance pipeline in CI (S4) | `build-windows.yml` runs the `afni_proc.py` pipeline of `tests/pipeline` (D34 options, anatomy with skull, so `3dSkullStrip` runs inside; QC off; `3dClustSim` for `sub-08` only) on `ds000102` subjects 08, 01, 02, 03, all four at once, followed by a group analysis (`group.tcsh`: intersection mask, `3dttest++` on incongruent−congruent, `3dMVM` with condition as within-subject factor). Windows (`pipeline-windows`): the release installer installed silently; data and work directories under a Cyrillic folder name; `afni_proc.py` started from `cmd.exe` through its launcher, the proc scripts through `tcsh.cmd`, the group script typed into the AFNI shell; PATH holds only the AFNI directory and the Windows system directories. Linux (`pipeline-linux`): the programs of the reference build with the upstream scripts and `afnipy` of the same tag in one directory, system `tcsh` and Python, R of the same version with the Linux binaries of the same package snapshot. Criteria (S0 report section 8), checked in `compare`: every compared output of every subject and of the group within `tests/pipeline/tolerance.json` (registration class of D29 per value, at most 0.1 % of the values of a dataset beyond it; ACF estimate and `3dClustSim` attributes reported only), and the wall time of the four subjects on Windows at most 1.5 times the Linux time of the same run (group time reported). `OMP_NUM_THREADS=1` and `AFNI_RANDOM_SEEDVAL` on both platforms. | `tests/pipeline/`, `.github/workflows/build-windows.yml` |
